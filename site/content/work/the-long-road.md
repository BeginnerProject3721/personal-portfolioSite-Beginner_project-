### 목적과 기획

스크롤만으로 하나의 게임 속 여정을 경험하는 듯한 인터랙티브 웹사이트를 만들고자 했습니다. 방문자가 스크롤을 내릴 때 인물이 앞으로 나아가고 주변 풍경이 달라지도록 구성해, 직접 이야기를 진행하는 느낌을 주는 데 초점을 맞췄습니다.

전체 흐름은 한 인물이 초원과 숲, 사막, 설산 등 다양한 장소를 지나가는 여정으로 기획했습니다. 장면마다 색감과 분위기에 변화를 주면서도 인물의 이동이 이어지도록 해, 여러 풍경이 하나의 이야기로 연결되게 하고 싶었습니다. 마지막에는 인물이 하늘을 가르는 장면을 넣어 여정의 절정을 표현하고, 방문자에게 인상적인 마무리를 남기고자 했습니다.

### 본인 역할과 제작 과정

The Long Road는 개인 프로젝트로 진행한 작업물입니다. 저는 작품의 전체 기획과 연출 방향을 정하고, 구현 결과를 확인하며 수정할 부분을 판단하는 디렉터 역할을 맡았습니다. 코드 구현에는 Claude를 활용했으며, 세부적인 개발 로드맵을 정해 기본 구조부터 세부 연출까지 단계적으로 발전시켰습니다.

<details class="work-process-detail">
<summary>장면 구성과 개발 순서</summary>

먼저 초원·숲·사막과 인물의 걷기 동작, 스크롤에 따른 장면 전환을 구현했습니다. 이후 설산·호수·폭풍을 추가하고, 마지막에 인물이 멈춰 칼을 뽑고 하늘을 가르는 흐름을 구성했습니다. 전체 흐름이 갖춰진 뒤에는 인물의 움직임과 칼의 궤적, 충격파, 빛과 날씨 효과를 다듬었습니다.

</details>

<details class="work-process-detail">
<summary>풍경 표현과 코드 구조</summary>

Three.js로 3D 장면과 카메라, 렌더링을 구성하고, GLSL 셰이더로 풍경을 표현했습니다. 별도의 이미지나 3D 모델 파일 없이 도형과 수학적 함수를 이용해 화면을 만드는 방식입니다.

예를 들어 아래 코드는 서로 다른 크기의 노이즈를 다섯 번 겹쳐 산과 사구 등에 사용할 불규칙한 윤곽을 만드는 함수입니다.

```glsl
float fbm1(float x) {
  float s = 0.0, a = 0.5;
  for (int i = 0; i < 5; i++) {
    s += a * n1(x);
    x = x * 2.03 + 17.1;
    a *= 0.5;
  }
  return s / 0.97;
}
```

반복할 때마다 노이즈를 더 촘촘하게 만들고 영향은 절반으로 줄여, 큰 굴곡 위에 작은 굴곡을 더합니다. 이를 통해 단순한 곡선보다 자연스러운 지형의 형태를 표현할 수 있습니다.

</details>

<details class="work-process-detail">
<summary>인물의 움직임과 마지막 연출</summary>

인물은 갑옷 형태의 도형들을 조합해 구성하고, 가장자리에 빛을 더해 실루엣을 드러냈습니다. 걷기는 뼈대와 IK를 이용해 발이 지면에 붙는 움직임을 표현했으며, 칼을 뽑고 휘두르는 동작은 자세 키프레임으로 구성했습니다.

하늘을 가르는 장면은 하늘만 별도로 그린 뒤, 베기 선을 따라 양쪽으로 밀어내고 틈 사이로 새벽빛이 나타나도록 구현했습니다. 짧은 시간 정지와 카메라 움직임을 함께 사용해 동작의 타격감을 강조했습니다.

</details>

<details class="work-process-detail">
<summary>결과 확인과 수정</summary>

구현된 화면을 확인하면서 의도와 다른 부분은 수정 방향을 정해 다시 요청했습니다. 여러 차례 수정해도 자연스럽지 않았던 망토는 제거하고 긴 칼집으로 대체했으며, 하늘이 열릴 때 화면이 지나치게 밝아지는 현상과 칼집이 다리에 겹쳐 보이는 부분도 조정했습니다. 실행 성능에 따라 해상도와 입자 수를 조절하고, ‘동작 줄이기’ 설정에 대응하는 기능도 포함했습니다.

</details>

### 사용 도구와 선택 이유

<details class="work-process-detail">
<summary>Claude — 기획을 코드로 구현하는 협업 도구</summary>

직접 기획한 장면과 기능을 코드로 구현하고, 결과를 보며 수정하는 과정에 활용했습니다. 작업을 단계별로 나누어 요청하고, 코드의 구조나 구현 방법에 관해 질문하면서 개발을 이어갈 수 있다는 점에서 선택했습니다.

</details>

<details class="work-process-detail">
<summary>Three.js — 브라우저에서 표현하는 3D 장면</summary>

장면과 카메라를 구성하고 화면을 렌더링하는 데 사용했습니다. 별도의 프로그램 설치 없이 웹 브라우저에서 입체적인 공간과 움직임을 보여주려는 작업 방향에 적합했습니다.

</details>

<details class="work-process-detail">
<summary>GLSL 셰이더 — 코드로 만드는 풍경과 효과</summary>

산·사구·구름 등의 풍경과 빛, 하늘이 갈라지는 효과를 표현하는 데 사용했습니다. 이미지 파일을 배치하는 대신 수학적 함수와 계산으로 장면을 만들고, 스크롤 진행에 따라 색감과 형태를 변화시키기 위해 활용했습니다.

</details>

<details class="work-process-detail">
<summary>GSAP·Lenis — 스크롤과 장면의 연결</summary>

스크롤 위치에 따라 장면과 연출을 제어하고, 화면 이동을 부드럽게 만드는 데 사용했습니다. 스크롤이 곧 여정의 진행으로 느껴지도록 하려면 입력과 장면 변화가 자연스럽게 이어지는 것이 중요했기 때문입니다.

</details>

### 결과와 배운 점

<details class="work-process-detail">
<summary>완성한 결과</summary>

스크롤에 따라 여섯 가지 풍경이 이어지고, 마지막에는 인물이 하늘을 가르는 인터랙티브 웹사이트를 완성했습니다. 인물의 움직임과 장면 전환, 빛과 날씨 효과를 연결해 처음 기획했던 게임 속 여정과 같은 경험을 표현했습니다.

</details>

<details class="work-process-detail">
<summary>AI와 협업하는 방법</summary>

작업을 작은 단계로 나누고 원하는 동작과 표현을 구체적으로 전달하는 것이 중요하다는 점을 배웠습니다. AI가 만든 결과를 확인한 뒤, 어떤 부분이 의도와 다른지 설명하고 수정 방향을 정하는 과정이 완성도에 큰 영향을 주었습니다.

</details>

<details class="work-process-detail">
<summary>추가보다 중요한 선택과 수정</summary>

망토를 여러 번 수정해도 원하는 모습이 나오지 않아, 최종적으로 제거하고 긴 칼집으로 인물의 실루엣을 정리했습니다. 이 경험을 통해 효과나 요소를 많이 넣는 것보다, 작품에 어울리는 요소를 선택하고 불필요한 부분을 덜어내는 판단이 중요하다는 것을 배웠습니다.

</details>

<details class="work-process-detail">
<summary>보이는 화면 너머의 완성도</summary>

화려한 장면뿐 아니라 실행 성능과 사용 환경도 함께 고려해야 한다는 점을 배웠습니다. 해상도와 입자 수를 조절하고 ‘동작 줄이기’ 설정에 대응하는 과정을 통해, 화면이 멋있게 보이는 것과 편하게 사용할 수 있는 것을 함께 생각하게 되었습니다.

</details>

### 한계와 개선 방향

<details class="work-process-detail">
<summary>다양한 기기에서의 성능 확인</summary>

장면별 화면과 오류를 확인했지만, 다양한 PC와 휴대폰에서의 실행 성능은 충분히 검증하지 못했습니다. 앞으로 실제 기기에서 프레임 속도와 스크롤 반응을 확인하고, 결과에 따라 해상도와 효과의 표현량을 조정할 계획입니다.

</details>

<details class="work-process-detail">
<summary>모바일 화면에 맞춘 연출</summary>

화면 크기에 따른 품질 조정은 적용했지만, 세로로 긴 모바일 화면에서도 인물과 주요 효과가 잘 보이는지는 추가 확인이 필요합니다. 화면 비율에 맞춰 카메라 거리와 구도를 조정하고, 터치로 스크롤할 때도 장면 전환이 자연스럽게 이어지도록 개선하고자 합니다.

</details>

<details class="work-process-detail">
<summary>음원 용량 줄이기</summary>

배경 음악을 HTML 파일에 포함하면서 전체 파일 용량이 커졌습니다. 음질과 용량을 비교해 적절한 비트레이트를 선택하고, 반복 가능한 음악 구간을 활용하는 방법을 검토해 파일을 더 가볍게 만들고자 합니다.

</details>

<details class="work-process-detail">
<summary>코드 이해와 직접 수정하는 능력</summary>

Claude를 활용해 구현하면서 주요 코드의 구조와 동작을 살펴봤지만, 모든 기능을 충분히 이해하고 직접 수정할 수 있는 수준에는 아직 한계가 있습니다. 앞으로 스크롤 처리, 장면 전환, 인물의 움직임을 기능별로 나누어 분석하고, 값을 직접 변경한 뒤 결과를 비교하면서 이해를 넓혀갈 계획입니다.

</details>
